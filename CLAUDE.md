# KDE Customizer

Builds complete KDE Plasma 6 themes from a single TOML spec, and installs/applies them.
Target system: Plasma 6.8, Qt 6, Python 3.11+ (dev box runs 3.14, CachyOS).

## Architecture
- `src/kdecustomizer/spec.py` — `Theme` dataclasses = the spec. TOML in (`tomllib`), TOML out (tiny hand-rolled writer).
- `color.py` — hex/RGB helpers; `shift()` moves a color away from the background (lighter on dark themes).
- `generators/` — one module per output artifact, each a pure function `Theme -> str`. No I/O.
- `build.py` — writes everything to `build/<Slug>/` **plus a standalone `install.sh`**. Installing/applying always goes
  through that script (CLI and GUI both run it), so built themes are shareable without this tool.
- `spec.fix_id()`: a named theme with a placeholder id (`org.kdecustomizer.untitled`) gets `id_for(name)` on load/save.
- `cli.py` (`kdec`) and `gui/app.py` (`kdec-gui`, PySide6) are thin front ends — keep logic in core modules.
- `snapshot.py` — `kdec snapshot` / GUI "From Desktop": reads the live config (KConfig cascade: `$XDG_CONFIG_DIRS`
  incl. `~/.config/kdedefaults` under `~/.config`) into a Theme. `surface` = `[Colors:Window] BackgroundAlternate`
  (what `colors.scheme()` writes), so our own schemes round-trip exactly. Assets marked "generated by kde-customizer"
  come back as `generate = true` (icon/cursor base from their index.theme). Panels: screen 0's only.
- `system.py` — lists installed icon/cursor/Plasma/widget styles (editor dropdowns + AI prompt).
- `ai.py` — provider-neutral AI design. Default provider `claude-code` runs `claude -p` (user's Claude Code login,
  no API key; API-key env vars are stripped; only the Read tool, for a temp wallpaper copy). `reference()` (spec guide + installed themes), `parse_reply()`,
  `check()` (contrast + not-installed), `generate()` (Claude via `anthropic` SDK; others via OpenAI-compatible
  `/chat/completions` with urllib; one automatic fix-up round when `check()` complains).

## Icons
- `iconset.py` — generated icon theme `<Slug>-Icons`: recolors the base theme's folder/place SVGs (hex fills
  near the base's dominant folder hue -> accent, HLS shift) and `Inherits=` the base. Papirus color variants
  (`folder-red*`…) and symbolic icons are skipped. Any icon name present in our theme must exist in all the
  base's sizes for it, or KDE won't fall back to the base for missing sizes.
- `appicons.py` — `app_icons = "recolor"`: every visible app's icon (`Icon=` of .desktop files incl. Flatpak
  exports; found along the base theme's Inherits chain, user hicolor uses hicolor's index) rendered at 256 px;
  `find_plate()` = ring just inside the edges (else dominant color) — the plate is redrawn as a graphite gradient
  + accent rim (Qt Difference-blend mask), the logo keeps its colors (dark unsaturated logos inverted); no plate =
  left alone. Written as SVG-wrapped PNGs in `apps-recolored/scalable` (after signature dirs, which win).
- Own icons (`[iconset] custom_dir`): a folder of `<icon-name>.svg|png` (subfolders searched, SVG wins). `iconset.build`
  writes them first into `custom/scalable/<context>` (PNG wrapped in a square SVG, no Pillow/Qt needed), listed first
  in index.theme, and leaves those names out of every other layer. `iconnames.py` = `CATALOG` (name, category,
  purpose), `theme_index(base)` (every name along the Inherits chain -> file, cached), `installed_apps()` (icon ->
  app name, cached), `unknown_names()` (typo warning, also in `ai.check`). GUI: Icons › Your own icons +
  `gui/icon_names.py` (Icon Names window). Bundled in builds as `custom-icons/`; `spec.save()` stores paths inside
  the spec's folder relative (wallpaper, signature_dir, custom_dir).
- `signature.py` — 14 `SLOTS` made custom: `svg` (AI JSON of SVGs, sanitized), `image` (local image AI), or
  `import`. Stored in `<spec dir>/<slug>-icons/{svg,png}/<slot>.*`; they replace recolored versions.
- `imagegen.py` — checkpoint choice: `Backend.models()` / `default_model()` / `chosen_model()` (`model` =
  name | "auto" → `pick_model()` by name: Juggernaut/RealVis/DreamShaper…, never inpaint/refiner/Pony/anime/
  Lightning/Turbo | "" = default). Fooocus: the "Base Model (SDXL only)" dropdown value; A1111:
  `override_settings.sd_model_checkpoint` per request; ComfyUI: `ckpt_name`. GUI remembers it in QSettings.
- `imagegen.py` — Fooocus (Gradio 3 queue over a stdlib websocket; settings matched by label), ComfyUI,
  A1111/Forge. `to_icon()` cuts the background with rembg — imported here, or through another Python that has
  it (`$KDEC_REMBG_PYTHON`, the cached one, or the running image AI's venv found via /proc: Fooocus/ComfyUI/A1111
  ship rembg + onnxruntime) using the best model already in ~/.u2net — else a flood fill that spreads through
  backdrop-colored pixels or smooth steps only (keeps light metal behind crisp edges, every piece ≥1% of the
  largest). Raw renders are kept in `<sig>/raw/` so `signature.recut()` / `kdec icons --recut` / "Re-cut
  backgrounds" can redo the cut-out without the GPU.
  Running image gens uses the user's GPU — test with `--only` and a couple of icons.

## Cursors (`[cursorset] generate = true`)
`cursorset.py` → `build/<Slug>/cursors/<Slug>-Cursors/` (installed to `$DATA/icons/`, applied with
`plasma-apply-cursortheme`): recolors the base's `cursors_scalable/<name>/*.svg` (KWin/Wayland; `metadata.json`
holds hotspot in SVG px, nominal size, frame delay) — unfilled bodies get the root `fill`, blurred shadows are
pinned black, grays slide body→outline by lightness, Breeze's colors map to palette roles. `cursors/` Xcursors
(X11/XWayland) are rendered from those SVGs with QtSvg at `XCURSOR_SIZES`; without PySide6 the base's are copied.
Aliases stay relative symlinks. Only bases with `cursors_scalable/` work (`scalable_themes()`).
Check with a contact sheet: parse the Xcursor images and paint them on dark + light backgrounds.

## GTK 4 / libadwaita (`[gtk] generate`, on by default)
`generators/gtk.py` → `build/<Slug>/gtk/kde-customizer.css`: libadwaita colors from `colors.scheme()`, written as CSS
variables (`--window-bg-color`, libadwaita 1.6+) and named colors (`@define-color window_bg_color`, older runtimes).
`install.sh` copies it to `~/.config/gtk-4.0/` and inserts `@import 'kde-customizer.css';` after the last `@import`
in gtk.css (KDE's GTK integration owns gtk.css's `colors.css` import and rewrites colors.css, not gtk.css); themes
with `generate = false` remove that line and file. `flatpak = true` adds `flatpak override --user
--filesystem=xdg-config/gtk-4.0:ro`. Check with a real libadwaita window: `/usr/bin/python3` + gi Adw, a temp
`XDG_CONFIG_HOME`, `Gtk.WidgetPaintable` → `render_texture` → PNG (no screenshot needed).

## Other terminals / editors (`[apps]`, all on; only where installed)
`generators/apps.py` → `build/<Slug>/apps/`: kitty `.conf`, Alacritty `kde-customizer.toml`, WezTerm scheme `.toml`,
Ghostty theme, VS Code `.vsix` (zip: `[Content_Types].xml`, `extension.vsixmanifest`, `extension/package.json`,
theme JSON; installed with `code --install-extension`). Terminal colors = `konsole.ansi()`; VS Code workbench =
`colors.scheme()`. install.sh: kitty/Ghostty get a `# BEGIN_KDEC_THEME … # END_KDEC_THEME` block (rewritten each time,
removed when off); Alacritty's importing file overrides imports, so its `[colors.*]` tables get a `#kdec# ` prefix
(one-time `.kdec-backup`), our file goes first in `general.import`; turning it off restores the file byte-for-byte.
VS Code settings.json is never edited (JSONC). Check a vsix with `code --extensions-dir <tmp> --install-extension`.

## Boot splash (`[boot_splash] generate = true`, opt-in)
`generators/bootsplash.py` → `build/<Slug>/boot/kdec-<slug>/` = Plymouth `script` theme (`.plymouth`, `.script`, PNGs
written with zlib — the script plugin loads PNG only) + `boot/apply.sh` (root: copies to
/usr/share/plymouth/themes, `plymouth-set-default-theme -R` = initramfs rebuild, prints how to go back).
The script must keep the disk-unlock prompt working: SetDisplayPassword/Question/Normal/Message callbacks.
`install.sh` runs login/apply.sh and boot/apply.sh in ONE pkexec, for whichever part's hash stamp changed
(`~/.local/state/kde-customizer/{login,boot}-<Slug>`). plymouthd only runs as root, so the visual check is CI's
`boot-test` job (Xvfb + Plymouth's x11 renderer, screenshots uploaded as an artifact). Test hook: KDEC_BOOT_ROOT.

## Login screen (`[login_screen] generate = true`)
Two greeters, picked at install time from `display-manager.service` (else whichever greeter user exists):
- Plasma Login Manager (`plasmalogin`, Plasma 6.6+, this dev box): compiled QML greeter running as user
  `plasmalogin` (home `/var/lib/plasmalogin`); wallpaper in `/etc/plasmalogin.conf`
  `[Greeter][Wallpaper][<plugin>][General]`, images in `~plasmalogin/wallpapers/`.
  Source: invent.kde.org/plasma/plasma-login-manager (`src/frontend/kcm/`).
- SDDM (`sddm`, home `/var/lib/sddm`), Breeze SDDM theme from plasma-desktop: `/etc/sddm.conf.d/kde_settings.conf`
  `[Theme]` Current/CursorTheme/Font; `type`/`color`/`background`/`showClock` in
  `/usr/share/sddm/themes/breeze/theme.conf.user` (wallpaper copied next to it). Source: plasma/sddm-kcm.
Both greeters read their user's `~/.config/{kdeglobals,plasmarc,kcminputrc}` and `~/.local/share`.
`generators/loginscreen.py` → `build/<Slug>/login/apply.sh` (root: detects the DM, stages assets, `runuser`s
`greeter.sh`, writes the system config) + `greeter.sh` (as the greeter user: copies assets, merges keys with
kwriteconfig6, clears its cache). `install.sh` runs `pkexec bash login/apply.sh` once and stores a hash in
`~/.local/state/kde-customizer/login-<Slug>` to skip the password prompt when nothing changed; `--no-login` skips it.
Test without root: `KDEC_LOGIN_ROOT=<tmp> KDEC_LOGIN_HOME=<tmp home> KDEC_LOGIN_DM=sddm|plasmalogin bash
login/apply.sh build/<Slug>` writes everything under <tmp>. For Plasma Login, then run
`HOME=… XDG_CONFIG_HOME=… XDG_DATA_HOME=… XDG_CACHE_HOME=… /usr/lib/plasma-login-greeter --test` (full screen,
gray background — the wallpaper is a separate process) and screenshot it.

## GUI
Window = `gui/app.py` `Main`: only the frame (toolbar, Output dock, start page <-> editor). Its work is in mixins that
share `self` (state like `self.theme`, `self.text`, `self.colors` is created in `Main.__init__`):
`gui/pages/{theme,colors,desktop,panels,fonts,tweaks}.py` build one section each (`pages/__init__.FormHelpers` =
`_form_page`/`_group`/`_line`), `gui/editing.py` = form <-> Theme, reactions to edits, preview/compare/icon preview,
undo, autosave; `gui/files.py` = new/open/save/shared themes/drops; `gui/desktop_actions.py` = build, export, Apply,
Undo Apply, installed themes, setup check, update notice; `gui/fields.py` = ColorField, FontField, TWEAK_PRESETS,
COMMON_WIDGETS, POPUPS, `combo`, `scroll`. Put new code in the mixin it belongs to, not in app.py.
Mixins import relative to their folder (`pages/` modules use `from ... import spec`, `from ..fields import …`).
`build._write_install_script` = one helper per install.sh step (`_header_lines`, `_copy_lines`, `_apply_lines`,
`_settings_lines`, + the GTK/terminal/browser/VS Code/variant/follow/system ones); check a refactor by diffing the
install.sh of every example/starter before and after.
`gui/app.py` = editor sections (left; `gui/sections.py` = sidebar list + stack with QTabWidget's API, so
`self.tabs` still has addTab/tabText/setCurrentIndex) + `gui/preview.py` live preview (right) + `gui/ai_panel.py` on top.
"Compare with my desktop" (`gui/compare.py`): `snapshot.take()` once, both sides rendered by offscreen Previews
(resizing the live one, a page of the same stack, loops) with a draggable divider; follows edits via `_show_preview`.
Autosave: `_commit()`/`set_theme(dirty)` write `library.autosave()` (`$XDG_STATE_HOME/kde-customizer/autosave/`);
a window only ever clears the copy it wrote (`_kept`), so another session's leftovers wait for the start page's
Recover/Discard banner. Apply: `gui/apply_summary.py` lists `always()` + skippable `parts()` → install.sh args
(`build.SKIP_PARTS`, `--no-*`; skipped = untouched, not undone; unticked remembered in QSettings per theme id).
`gui/setup_dialog.py` = `doctor.py` (`kdec doctor`: optional tools + per-distro install commands from os-release),
rows filled from `doctor.run_iter()` on a QThread (don't name it `self.thread`: QObject.thread() exists).
Apply builds first, then the summary: `build.unchanged_system_parts()` (login/boot hash = `build.tree_hash`, computed
in Python and written into install.sh as a literal) says when no password is needed. install.sh ends by writing
`build.spec_hash(original theme)` to `$STATE/installed-<Slug>`; `installed.outdated()` compares recent specs with it
(Installed… › Update, start-page count). `failures.explain()` turns install.sh output into plain-language causes
(Apply window, `kdec apply` hints). `gui/history_dialog.py` = Undo Apply's arrow (any restore point).
`gui/finder.py` = Find a setting (Ctrl+F): indexes labels/buttons/group titles of every section, label matches
before tooltip matches, `reveal()` scrolls, focuses and outlines. Preview `vision` = `vision.py` (Machado matrices,
Pillow `convert(matrix)`; the menu is hidden without Pillow). `updates.py`: AppImage (`$APPIMAGE`) or the tarball
(`update-check` marker next to `python/`, made by build-packages.sh, copied by packaging/install.sh) check GitHub's
latest release once a day (QSettings `updates/*`); start-page banner. `store.py` = `kdec export --store` / Export ›
For the KDE Store (one archive per part + UPLOAD.md + preview.png in the GUI).
Shared themes: `library.unpack_shared()` (refuses links/escapes, needs `<dir>/theme.toml`) into `themes_dir()`;
the GUI opens the spec and rebuilds, never runs the archive's install.sh. Drops: `.toml` opens, `.tar.gz` installs.
Colors › Variations: `variations.py` (accent ±30°/opposite, warmer/cooler = neutrals tinted to a hue, contrast,
saturation; all through `variant._readable`), `gui/variations_dialog.py` previews them; `_set_palette` = one undo step.
The preview paints a mock desktop on a fixed 1280x800 canvas from `colors.scheme()` / `konsole.ansi()` — the
same functions the generators use, so never derive colors in the GUI. Icons come from the theme's icon set via
`IconCache` (temporarily switches `QIcon.themeName`). AI work runs in a QThread; connect worker signals to
bound methods of a widget (lambdas would run on the worker thread). AI provider settings live in QSettings
(`~/.config/kdecustomizer/kdec-gui.conf`).
The preview paints into a QImage first, so translucent Plasma surfaces can blur what is already drawn behind them
(`_blur_behind`, when `[plasma] blur`). Popups (`Preview.popup`, "Show:" selector or click the panel item):
`_launcher` (Kickoff), `_calendar` (clock), `_tray`, placed by `_place()` next to the item recorded in `_anchors`;
`_dialog` = modal message box over the Files window (parent dimmed like KWin's dialogparent effect). Tweaks tab = a File/Group/Key/Value table ↔ `theme.tweaks`
(`TWEAK_PRESETS` adds common rows; values parsed to bool/int/float/str).
Offscreen screenshots for checking UI changes: `QT_QPA_PLATFORM=offscreen`, `w.grab().save(...)`.
Start page (`gui/start.py`, stack page 0 when no spec is given): `library.recent()` (`$XDG_STATE_HOME/kde-customizer/
recent.json`, added on load/save) + `library.starters()` (package data `starters/*.toml`, opened as unsaved new
themes), thumbnails = an offscreen `Preview` grabbed at 640x400 (cards need a fixed sizeHint: icons arrive later).
Undo/redo: whole-Theme snapshots (`_commit()` after 0.6 s idle, or before/after AI and image-palette changes);
a new theme (`_fresh`) resets the history. Problems strip = `ai.check()` 0.4 s after an edit, links `tab:N`.
`gui/apply_dialog.py` runs install.sh itself: `==> step` lines become a checklist, then "Keep these changes?"
for `KEEP_SECONDS` — timeout/Esc/Undo runs the restore point created during this run (set difference of
`restorepoints.points()`). `gui/manager.py` = `installed.py` (LnF packages with `X-KDE-Customizer-Slug` in
metadata, or `org.kdecustomizer.*` ids; parts found by install.sh's names; "<Name> Light|Dark" grouped as
variants; in-use ones can't be removed). `imagepalette.py`: k-means on ~4k pixels (Qt or Pillow), lightness set
like `variant.palette()`, colors moved with `variant._readable()`.

## Performance (measured on this box; keep these when changing the code)
- Caches, all keyed by the XDG data dirs + HOME (so tests and other folders never get a stale result):
  `appicons.IconFinder.get(base)` (icon file index, 240 → 0 ms after the first), `appicons.installed_apps()`
  (.desktop scan, shared with `iconnames`), `iconnames.theme_index()`. `iconset._canonical_entries` is cached per
  folder until its mtime changes. Pass `refresh=True` to re-read. Scans use `os.scandir` + string ops: a `Path`
  per file cost ~2 s on big themes.
- GUI icon preview (`_build_preview_icons`) runs on a worker thread into `preview-icons/set0|set1` (alternating, the
  search path switches when done; one build at a time, the newest edit is built next): ~0.1 s, was 0.38 s on the
  GUI thread per accent change.
- Preview wallpapers: decoded once, cut to the 1280×800 canvas and shared by every `Preview` (`_WP_CACHE`, 6 kept);
  an 8K image was ~66 MB per preview and re-scaled on every paint.
- `cursorset`: each SVG parsed once for all sizes. `build.tree_hash`: `os.walk` + `hashlib.file_digest`.
- `appicons._dist` = `math.dist` (called ~100k times per icon by `find_plate`).
- Reference timings: preview paint ~4 ms, `ai.check` ~6 ms, full build ~135 ms (mostly Xcursor rendering),
  colors from an 8K image ~150 ms (mostly decoding).

## Window decoration (`[decoration] generate = true`)
`generators/aurorae.py` → `build/<Slug>/aurorae/<Slug>-Decoration/` (installed to `$DATA/aurorae/themes/`):
`decoration.svg` (FrameSvg, prefixes `decoration-` / `decoration-inactive-`), one SVG per button with
`active|hover|pressed|inactive|deactivated-center`, `<name>rc` (sizes, title colors), metadata. The frame
covers shadow padding + title bar + borders; pieces may reach under the client window, only their bounding sizes
matter, and the stretched middle must be constant. KWin name: `__aurorae__svg__<Slug>-Decoration`
(`Theme.decoration_kwin`). Colors are plain hex from `colors.scheme()["WM"]` (Aurorae isn't recolored).
The engine's QML is in `/usr/share/kwin/aurorae/` — read it for element names and layout.

## App style (`[widgets] generate = true`)
`generators/kvantum.py` → `build/<Slug>/kvantum/<Slug>/<Slug>.{kvconfig,svg}` (installed to `~/.config/Kvantum/`).
kvconfig = one section per widget (element names, `frame.*` thickness — frame pieces are scaled to it — and text
colors); SVG = `<el>-<state>` interior + `<el>-<state>-top|…|bottomright` frame per state (normal, focused = hover,
pressed, toggled, disabled), plus indicators (arrows, checkbox/radio, slidercursor). An empty element = draw
nothing. Colors all come from `colors.scheme()`. LnF sets `widget_style` (the fallback); `install.sh` switches
kdeglobals to `kvantum` only if Kvantum is installed. Test with the real plugin, without touching the user's
config: copy the build into `<tmp>/Kvantum/`, then run `/usr/bin/python3` (system PySide6 — the venv's Qt can't
load the system plugin) with `XDG_CONFIG_HOME=<tmp> QT_STYLE_OVERRIDE=kvantum QT_QPA_PLATFORM=offscreen`.
Reference themes: `/usr/share/Kvantum/` (KvFlat is the closest to ours).

## Splash screen (`[splash_screen] generate = true`)
`generators/splash.py` → `contents/splash/Splash.qml` in the LnF (+ `images/background.*` = the wallpaper, when
`background = "wallpaper"`), and ksplashrc `Theme` = the LnF id (`Theme.splash_name`). ksplashqml raises the root's
`stage` 1→6; ours fades in from stage 2 and fills a bar with stage/6. Only QtQuick + Kirigami. Render offscreen with
`/usr/bin/python3` (system PySide6 has Kirigami): QQuickView on Splash.qml, set `stage`, `grabWindow()`.
`ksplashqml --test <lnf id>` shows it for real (full screen, a few seconds).

## What Look-and-Feel can and can't do
`plasma-apply-lookandfeel` only applies the keys in `contents/defaults` (colors, widget style, icons, plasma style,
cursors, decoration, splash) and the layout JS with `--resetLayout`. Anything else (fonts, decoration buttons,
KWin effects, arbitrary `tweaks`) is written by `install.sh` with `kwriteconfig6`, then `qdbus6 org.kde.KWin /KWin reconfigure`.

## Tests
`tests/` (pytest; `pythonpath` set in pyproject). `conftest.py` gives every test a temp HOME + XDG dirs (autouse) and a
fake `breeze_cursors` base (`cursor_base`). An autouse guard puts do-nothing stand-ins for pkexec/sudo (they refuse), plasma-apply-*, qdbus6, dbus-send,
systemctl, code, flatpak, xdg-open… first on PATH: a script that runs by mistake can't reach the session or root.
Never let a test run install.sh through an unpatched code path. GUI tests run offscreen (skip without PySide6); login-script tests use the
`KDEC_LOGIN_*` hooks (skip without kwriteconfig6); AI tests use a local fake OpenAI server, never a real provider.
CI's `test` job runs the suite in an Arch container and gates releases. Add a test with every generator/feature change.

```
kdec wallpaper mytheme.toml "idea"         # wallpaper in the palette via the local image AI
QT_QPA_PLATFORM=offscreen pytest -q        # test suite (pip install -e '.[gui,test]')
kdec ai "warm autumn, dock panel" [--from mytheme.toml] [--provider claude-code(default)|claude|openai|gemini|openrouter|ollama|lmstudio --model M]
kdec ai "..." --prompt-only                # prompt to paste into any chat AI
kdec ai-guide                              # spec guide for coding agents — read it before writing a theme spec
```
AI extras: `pip install -e '.[ai]'` (anthropic SDK + Pillow). Never run `kdec ai` against a real provider in
tests (it bills); use a local fake server on `--base-url` / `ANTHROPIC_BASE_URL`.
`apply` changes the live desktop — use `--dry-run` when testing generator changes.

## Plasma style (`[plasma] generate = true`)
`generators/plasmastyle.py` → `build/<Slug>/plasma/<Slug>/` = `metadata.json` + `colors` + `plasmarc`, **no SVGs** — same
trick as stock Breeze Dark: missing SVGs fall back to `default`, whose `ColorScheme-*` classes read the theme's `colors`.
`plasmarc` carries Blur/Contrast/AdaptiveTransparency hints.
Shapes: when `[plasma] radius/opacity/outline` differ from Breeze (6 / 0.85 / false), `plasmastyle.svgs()` also
writes FrameSvg SVGs (`dialogs/background`, `widgets/{panel-background,tooltip,background}`, in base,
`translucent/` and `solid/`): nine frame pieces + `hint-*-margin` + `mask-*` + `shadow-*` (+ panel `thick-*`).
FrameSvg only reads each element's bounding size, so pieces sit side by side on the canvas with no transforms.
Check shape changes by tiling the pieces with `QSvgRenderer.render(p, id, rect)` offscreen. `install.sh` copies it to `$DATA/plasma/desktoptheme/`
and deletes `~/.cache/plasma_theme_<Slug>*` so re-installs pick up new colors. `Theme.plasma_style_name` is what LnF sets.

## Restore points / `kdec revert`
`generators/restore.py` → `build/<Slug>/restore-point.sh`, run first by install.sh: writes
`$XDG_STATE_HOME/kde-customizer/restore/<time>-<Slug>/restore.sh` (newest 10 kept) = previous value of every key in
`restore.keys()` (BASE_KEYS + all_tweaks; read with `XDG_CONFIG_DIRS=/nonexistent` = user file only, unset →
`--delete`), a copy of `~/.config/kdedefaults/`, plasma-apply-* for color scheme/cursors/Plasma style/icons, the
wallpaper (plasmashell evaluateScript), copies of FILES (GTK, kitty, Ghostty, Alacritty) + Mozilla profiles, and

## Light/dark (`[light_dark] auto`)
`variant.py`: `opposite()` flips lightness (same hues; accent/status moved until readable), name "<Name> Light|Dark",
icon base swapped to its pair if installed. Built into `build/<Slug>/variant/<VSlug>/` (only the parts that switch);
install.sh installs its color scheme/styles/LnF without applying, sets kdeglobals `[KDE] AutomaticLookAndFeel`,
`DefaultLight/DarkLookAndFeel` (Plasma switches on Night Light's schedule). Kvantum isn't switched (fallback style).
`generators/lightdark.py`: user unit `kdec-follow.path` (PathChanged on kdeglobals — fires on KConfig's atomic save)
runs follow.sh, which copies `$DATA/kde-customizer/follow/<LnF id>/` files over GTK/kitty/Alacritty/Firefox CSS,
rewrites Ghostty's block and Konsole's DefaultProfile. Themes without auto turn AutomaticLookAndFeel off.

## Firefox / Thunderbird (`[apps] firefox/thunderbird`)
`generators/mozilla.py`: `chrome/kde-customizer.css` imported from each profile's userChrome.css (profiles.ini under
`ROOTS`: ~/.mozilla, ~/.config/mozilla (Firefox 147+), Flatpak, LibreWolf, Thunderbird) + user.js
`toolkit.legacyUserProfileCustomizations.stylesheets`. Variables are `!important` on :root (beats add-on themes);
both the current names (`--toolbar-background-color`, `--toolbox-background-color`, from omni.ja's
design-system tokens) and older ones are set. Check in a real window: `dbus-run-session -- kwin_wayland --virtual
--no-lockscreen --exit-with-session script` (firefox --no-remote --profile <tmp>, then `spectacle -b -n -f -o`).

## Wallpaper (`kdec wallpaper`)
`wallpaper.py`: prompt from the palette (`describe()` = color words), rendered at the SDXL size nearest the screen
(`Backend.size`; Fooocus via `closest_ratio()` on "Aspect Ratios"), scaled/cropped to `screen_size()` (kscreen-doctor),
saved as `<spec dir>/<slug>-wallpaper-<seed>.jpg`. GUI: "Make…" on the Desktop tab (uses the Icons tab's image AI).

## Wallpaper and Global Theme pictures
Plasma 6 applies a global theme's wallpaper only through the desktop layout: a layout reset (System Settings'
"Desktop and window layout", our `--layout`) makes plasmashell rebuild the desktop asynchronously, and new desktops get
`DefaultWallpaper` = the current LnF's `contents/defaults` `[Wallpaper] Image=<name>` -> the wallpaper *package*
`wallpapers/<name>` (else the Plasma style's default, else Breeze's "Next"). So install.sh turns `build/<Slug>/wallpapers/
<image>` into the package `$DATA/wallpapers/<Slug>/` (`metadata.json` + `contents/images/<W>x<H>.<ext>`,
`previews.wallpaper_file_name`), the LnF says `Image=<Slug>` (the light/dark variant points at the theme's package),
and `plasma-apply-wallpaperimage` gets the package folder. Source: plasma-workspace `libklookandfeel/
klookandfeelmanager.cpp`, `shell/shellcorona.cpp` (`loadLookAndFeelDefaultLayout`), `wallpapers/defaultwallpaper.cpp`.
LnF packages fall back to org.kde.breeze.desktop for missing files, so `previews.render()` writes
`contents/previews/{preview.png,fullscreenpreview.jpg,lockscreen.png}` (Breeze's sizes) from the editor's Preview —
needs PySide6 and the QApplication's thread (the CLI makes an offscreen one); skipped otherwise.

## Portability rule
Built output must not contain paths from the build machine. Wallpaper is bundled in `wallpapers/` and set by
`install.sh` via `plasma-apply-wallpaperimage "$DATA/..."`; the bundled `theme.toml` uses a relative wallpaper path.
